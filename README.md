# purplegold-init

[English](README.en.md)

用**紫金规范（Purple Gold）**初始化你的项目的 AI skill。

紫金规范是一套面向"人与 AI 协作"新工程形态的软件工程规范。核心理念是**一切皆是文档**：文档（而非代码）是项目的核心资产——即使代码全部丢失，凭紫金文档即可快速重建整个项目。

## 紫金规范概览

### 外骨骼规范：模块与合金文档

外骨骼规范管理工程文件夹中的所有模块及模块之间的关系，由 AI 阅读和维护：

- **模块认定**：扮演独立角色的文件或文件夹即为模块。每个文件夹模块有且仅有一份**合金文档**（模块内的 `ALLOY.md`），与模块同生同灭、同步更新。
- **合金文档**：以固定格式记录模块简介、子模块指针、内部关系、边界关系、父模块指针、接口与行为约定等七个必备小节；内部关系用严格的 mermaid 子集表达，是依赖关系的唯一权威表征。
- **依赖规则**：依赖只允许发生在同级模块之间，必须无环；跨层级的依赖改为父模块之间的依赖来表达。
- **脚本保证一致**：`align.py` 聚合各模块信息生成根模块派生区（全工程模块索引、内部关系总览等）；`validate.py` 校验文档声明与实际目录结构是否一致，不通过则不能收尾。

### 内骨骼规范：脊椎流程（八阶段主线）

脊椎流程是项目前期设计与开发的主线，八个阶段按顺序推进；各阶段产物写入 `紫金产物/脊椎产物/`：

| 阶段 | 内容 | 主要产物 |
|---|---|---|
| S01 需求确认 | 把需求谈清楚 | 需求确认清单、约束与非功能需求、用户角色定义、业务术语表 |
| S02 功能初步设计 | 功能与业务流程 | 功能清单、业务流程描述、范围声明（可选：用例集） |
| S03 功能交互设计 | 页面与交互 | 页面清单、页面流转图、逐页交互描述、用户操作路径、异常与空态规则 |
| S04 UI 视觉设计 | 视觉方案 | UI 设计需求（可选）、视觉稿、设计规范、组件清单、素材清单 |
| S05 工程架构与契约 | 技术方案落地 | 技术选型说明、模块架构设计、数据模型设计、接口与行为约定、外部服务接入清单 |
| S06 制定开发计划 | 任务与排期 | 任务分解清单、任务顺序与里程碑、任务完成判据、分工说明 |
| S07 开发和测试 | 写代码 | 代码、工程测试记录、偏差记录 |
| S08 实机测试和验收 | 真实环境验收 | 实机测试计划、用例库、实机测试报告、缺陷清单、验收对照表 |

脊椎流程是项目的根本驱动力：阶段产物允许修改，但任何阶段产物变化都要按阶段顺序回流检查其余各阶段。

### 内骨骼规范：肋骨规范（十三份预置）

肋骨规范是灵活规范的集合：不像脊椎流程那样线性推进，而是在特定时机必须执行、或由人类工程师按需启用；可按需裁剪或新增。按触发时机分两类：A 类有自动触发时机（AF 领先于脊椎流程，产物是脊椎流程的输入；AB 落后于脊椎流程，以脊椎产物为依据登记维护），M 类无自动触发时机、由人类工程师手动启用：

| 编号 | 规范 | 一句话说明 |
|---|---|---|
| AF01 | 提示词节点 | 每次发出提示词时记录为一个节点（序号、日期时间、原文、备注） |
| AF02 | 需求基线 | 每次输入含需求信息的提示词或文件时先更新需求总表及其变更记录——全部需求的最根本依据 |
| AB03 | 项目最新状态 | 状态变化时更新三份状态文档（脊椎流程进展、肋骨规范进展、外骨骼实现情况），只记最新状态 |
| AB04 | 脊椎产物变更记录 | 任何脊椎产物变更时追加一条记录（含回流检查结论） |
| AB05 | 需求追溯表 | 维护 需求 → 功能 → 页面 → 模块 → 任务 → 用例 的对照表 |
| AB06 | 美术素材备份 | 引用新美术素材时备份原件与派生变体并维护素材清单 |
| M01 | 部署和运维 | 何时部署、何时运维由人类工程师决定 |
| M02 | 修复和优化 | 每次会话记录修复与优化历史；涉及功能修复须复测 |
| M03 | 上架 | 商店分发形态项目（移动 App、小程序等）的上架管理 |
| M04 | 工作量评估 | 按固定计算方法评估大概工作量，供报价与宏观排期参考 |
| M05 | 甲方原始文件 | 按日期时间文件夹归集甲方提供的原始文件 |
| M06 | 对外文档 | 管理供甲方阅读的三种文档（需求与功能文档、交付边界文档、技术栈文档；MD 权威、DOCX 派生） |
| M07 | 账号密码管理 | 集中登记项目正式与测试账号（明文入库，前提：私有仓库） |

### 迭代器：版本与升级

项目通过 `purplegold/VERSION` 锚定所用规范版本；升级 = 用新版本实例模板整体替换 `purplegold/`，并按迭代记录迁移 `紫金产物/`。

## 这个 skill 做什么

在当前项目中执行紫金规范初始化：

1. 确保项目根为 Git 仓库根（没有则 `git init`）；
2. 复制内置实例模板，建立 `purplegold/`（静态规则层）与 `紫金产物/`（动态文档层骨架）；
3. 写入规范版本号，创建工程根 `project/` 与根模块合金文档 `project/ALLOY.md`；
4. 在 `AGENTS.md` 中加入指向 `purplegold/RULES.md` 的入口指针；
5. 运行对齐脚本与校验脚本，全部通过才算完成。

本 skill 为**自含包**：实例模板、脚本与规范版本号（`VERSION`）均内置，初始化全程离线可用。

## 安装

```bash
npx skills add wangfujian762/purplegold-init
```

或手动安装：把本仓库内容复制到你的 skills 目录下的 `purplegold-init/` 文件夹（如 `~/.agents/skills/purplegold-init/`）。

## 使用

前置条件：项目根可执行 `git`；环境有 Python 3（初始化收尾的对齐与校验脚本需要）。

在你的项目根目录对 AI 说：

> 用紫金规范初始化本项目。

Agent 会读取 `SKILL.md` 并按流程执行。初始化完成后，项目中的 AI 从 `AGENTS.md` 进入 `purplegold/RULES.md`，按紫金规范工作；脊椎流程从 `S01-需求确认` 阶段开始，`紫金产物/肋骨产物/AB03-项目最新状态/脊椎流程进展.md` 是整个项目的宏观待办清单。

## 初始化后的项目结构

```
<项目根>/
├── AGENTS.md       # AI 入口指针
├── purplegold/     # 静态规则层：规则、模板、脚本、脊椎规范与肋骨规范
├── 紫金产物/        # 动态文档层：项目产出的文档
└── project/        # 工程根：模块树，合金文档共置其中
    └── ALLOY.md    # 根模块合金文档
```

## 深入了解

规则的全部细则都在 skill 内置的实例模板中，初始化后也会出现在你的项目里：

- `实例模板/purplegold/RULES.md` —— 蒸馏规则，AI 的操作手册（模块认定、合金文档格式、脊椎流程、肋骨规范、状态文档维护）
- `实例模板/purplegold/脊椎规范/`、`实例模板/purplegold/肋骨规范/` —— 各阶段/各流程的规范文档
- `VERSION` —— 本 skill 内置的紫金规范版本
