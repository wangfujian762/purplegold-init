# 阶段 4 · UI 视觉设计

> 定位：产出全部页面的视觉稿，并从确认后的视觉稿中提取设计变量、复用组件与素材。
> 本文件是脊椎流程阶段 4 的蒸馏规范；产出文档写入 `紫金产物/脊椎产物/S04-UI视觉设计/`。

## 产物清单

产物按清单顺序产出；落在本阶段产物文件夹内的产物（文件或文件夹）以 `序号-名称` 命名（如 `02-视觉稿/`）。

| # | 产物 | 格式 | 内容说明 |
|---|---|---|---|
| 01 | UI 设计需求（可选） | Markdown | 本阶段设计要求的现行有效版本：从需求基线与会话沟通中汇总、去重、定稿的设计要求与已定案决策（视觉方向、文案定稿、借鉴元素、特效方案、主题策略），按主题组织。仅当人类工程师交代了 UI 设计要求时产出；产出后是 02 视觉稿的输入与验收依据 |
| 02 | 视觉稿 | React（Vite）前端工程 | 各页面的视觉设计稿，以可运行的前端工程形式制作：统一使用 React + Vite，可直接安装原版组件库，保证特效观感与最终实现一致，并可演化为阶段 7 的实现代码；界面中不得使用 emoji 作为图标、占位符或装饰 |
| 03 | 设计规范 | Markdown | 色彩、字体、字号、间距等设计变量（design tokens），从确认后的视觉稿中提取 |
| 04 | 组件清单 | Markdown | 复用组件及其变体的清单与说明，从确认后的视觉稿中提取 |
| 05 | 素材清单 | Markdown + 素材文件 | 图标、插图等素材的清单、文件与来源，从确认后的视觉稿中提取 |

> 注：修复缺陷类的要求不属于 UI 设计要求，不写入 01 UI 设计需求（见 `purplegold/RULES.md` 第 3 节）。
> 先后关系：UI 设计需求归 AF02-需求基线先行记录；需求更新时先更新需求基线，再按需对齐本阶段产物（见 `purplegold/RULES.md` 第 4 节）。

## 推进方式

- 本阶段分两个小步骤推进：第一步只产出 01 UI 设计需求（如有）与 02 视觉稿——先汇总 UI 设计需求（未产出 01 时，依据需求基线与会话沟通中的设计要求制作），据其制作视觉稿；视觉稿经人类工程师确认后才进入第二步。第二步产出 03、04、05——三份产物是视觉稿的附属产物，从确认后的视觉稿中提取，不是视觉稿的先决条件。
- 视觉稿的制作统一使用 frontend-design 技能（用户级技能库）作为执行方式；环境不具备该技能时，按同等标准执行。

## 完成判据

- 适用通用完成判据（见 `purplegold/RULES.md` 第 3 节）。特有判据：02 视觉稿经人类工程师确认后，方可登记 03～05 的产出。
